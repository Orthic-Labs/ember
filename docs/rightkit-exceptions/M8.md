# RightKit M8 (safe file writes): Ember's exceptions

> **Last updated:** 2026-10-19

Ember writes files through `rightkit-fs` 0.4.7: atomic writes, exclusive publishing, append records, the library lock, verified copies, the clone ladder, `copy_tree`, and `is_within` / `canonicalize_plain`. The old `crates/catalog/src/safe_file.rs` wrapper is deleted. What remains is `crates/catalog/src/written.rs`: the "replaced target counts as written" rule and the wasm32 stubs.

The four behaviours below stay in the app because the published crate has no equivalent. Each is recorded in [`.rightkit/ownership-exceptions.json`](../../.rightkit/ownership-exceptions.json) (capability `safe-filesystem`, package `rightkit-fs`). Each section gives four points:

1. Need: what the user loses if it is removed.
2. Published gap: why the published API can't do it.
3. Other apps: how they handle it.
4. Proof.

## 1. Journal torn-tail truncate

**Code:** `crates/catalog/src/store.rs`, `FsStore::truncate`. Appends go through `rightkit_fs::append_record`.

1. **Need.** A crash in the middle of an append leaves a torn final record in `catalog.log`. The journal cuts it back before the next append, so a retry can't glue a fragment onto a new record. Without this, a library could fail to load after a power cut, and edits made since the last snapshot would be lost.
2. **Published gap.** `rightkit-fs` `append.rs:16-20` leaves torn-tail repair to the app ("Torn-tail repair is a domain decision and stays in the app").
3. **Other apps.**
   - CodeRight keeps its own repair too: `journal_repair.rs:120-133` cuts a torn final record, and appends go through `rightkit-fs` (S1).
   - Two or more apps keep their own code, so this is a RightKit gap.
4. **Proof.**
   - `crates/catalog/src/tests_torn_append.rs`:
     - `partial_append_then_retry_loads_cleanly`
     - `failed_cut_back_is_done_before_the_next_append`
     - `legacy_fragment_glued_to_the_retry_is_skipped`
     - `snapshot_with_unlogged_ops_saves_them`
     - `fs_store_truncates_a_missing_file_quietly`
   - `store::tests_append::appends_are_flushed_and_a_torn_tail_is_cut_back_before_the_next_append`

## 2. Lightroom archive retention and quarantine

**Code:** `crates/engine/src/lightroom_archive.rs`, retention (8 archives / 128 MiB) and quarantine. The archive itself is published with `atomic_write_with_options` NoReplace.

1. **Need.** Each Lightroom catalog import keeps a byte-for-byte archive of the source catalog, so the user can go back. Ember keeps at most 8 archives or 128 MiB and retires the oldest. If retiring fails, the new archive is withdrawn and the old ones stay. A failed cleanup must never lose the archive the user just made, and archives must not grow without bound.
2. **Published gap.** `rightkit-fs` has no retention or quarantine API. Its trash (`trash.rs`; README "trash" entry) moves to the trash on macOS only (Windows `move_to_trash` is refused), and `publish_dir` publishes directories, not a retention set.
3. **Other apps.**
   - Pulse has its own rename-rotation at 4 sites (S2).
   - ScrapeRight has its own sweeps of staged copies (S2).
   - CodeRight has its own restorable trash on all OSes (S4).
   - CutRight has its own removal of read-only recording bundles (S4).
   - Two or more apps keep their own code, so this is a RightKit gap.
4. **Proof.** `lightroom_archive::tests`:
   - `retention_enforces_aggregate_byte_cap_with_small_synthetic_entries`
   - `retention_failure_preserves_old_archive`
   - `a_failed_retention_withdraws_the_new_archive_and_keeps_the_old_ones`
   - `dedup_returns_archive_that_retention_keeps`
   - `caps_managed_archive_count_and_preserves_unrelated_files`

## 3. Case-only folder rename

**Code:** `crates/engine/src/cmd/browse.rs`. A case-only rename (`Trips` → `trips`) on a case-insensitive volume goes through a temporary `.lc-rename-<pid>` name. A rename to a different name uses `rightkit_fs::rename_exclusive`.

1. **Need.** The user renames a folder only to change its case. Without the temporary step, the rename is refused on macOS and Windows default volumes, because the destination name already "exists" (it is the same folder).
2. **Published gap.** `rename_exclusive` (`atomic.rs:435`) sees the destination as existing and refuses. There is no case-only rename API in `rightkit-fs`; a grep for "case-only" finds nothing.
3. **Other apps.** None. No other app lists this need, so there is nothing to compare.
4. **Proof.**
   - `browse::tests::a_case_only_folder_rename_keeps_the_contents_and_leaves_no_temporary_name`
   - The different-name path is covered by `browse::tests::a_folder_rename_never_replaces_a_folder_that_is_there`.

**Related limit (not an exception).** On a volume with neither an exclusive rename nor hard links (FAT/exFAT cards, some shares on macOS and Linux), `rename_exclusive` refuses a plain folder rename. Nothing moves and nothing is lost, but the rename fails where Ember's old code renamed it. It is tested by `a_folder_rename_on_a_volume_without_exclusive_rename_changes_nothing` and reported to RightKit as a gap.

## 4. Backup and restore refuse every symlink

**Code:** `crates/desktop-host/src/controller.rs`. `refuse_symlinks`, a read-only `symlink_metadata` pre-walk, runs first. Then `copy_library` calls `rightkit_fs::copy_tree` once per top-level entry, with links kept as links so a race never follows one.

1. **Need.** A library backup or restore must not pull in the bytes of a file outside the library through a symlink planted inside it. This is a data-protection guard (lead rule 3).
2. **Published gap.** `rightkit-fs` `tree.rs:21-33` (`CopyOptions`) offers only two modes for a file link: `keep_symlinks: true` recreates the link, and `false` copies the target's bytes. Directory links are refused. There is no refuse mode and no entry filter.
3. **Other apps.**
   - CodeRight keeps its own read-only pre-walk that errors on any symlink before `copy_tree` (`file_service.rs`, `reject_symlink`), as a security guard (S3).
   - ScrapeRight keeps its own confined copy that refuses a symlink or junction at any path component (`history.rs`, S3).
   - Two or more apps keep their own code, so this is a RightKit gap.
4. **Proof.** `controller::tests`:
   - `library_copy_refuses_a_planted_symlink_before_copying_anything`
   - `library_copy_does_not_follow_a_link_that_appears_after_the_check`
