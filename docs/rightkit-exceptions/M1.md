# RightKit M1 (window host): Ember's exceptions

> **Last updated:** 2026-10-24

Ember's desktop app (`apps/lightcraft-desktop`) is on the M1 owners:

- rightkit-tauri-shell `=0.6.0`
- rightkit-device `=0.4.0`
- @rightkit/tauri `0.3.0`

The code the published API covers is deleted:

- **Second window:** created by `rightkit_tauri_shell::windows::open`.
- **Fullscreen:** goes through `rk_shell_window("fullscreen")`. An explicit on/off request toggles only when the window is not already in that state.
- **Ordinary close:** goes through `rk_shell_window("close")`.

Focus changes and file drops come from Tauri's own per-webview events (`onFocusChanged`, `onDragDropEvent` in `web/src/desktop.tsx`), so the native forwarding is gone.

One window behaviour stays in the app because the published API (shell 0.6.0) has no equivalent. It is recorded in [`.rightkit/ownership-exceptions.json`](../../.rightkit/ownership-exceptions.json) (capability `desktop-shell`, package `rightkit-tauri-shell`, RightKit issue [bogusyogi/rightkit#1150](https://github.com/bogusyogi/rightkit/issues/1150)) and explained below:

1. what the user loses if it is removed;
2. why the published API can't do it;
3. how other apps handle it;
4. proof.

The second window behaviour of the earlier ledger, QA viewport geometry, is gone: `native.rs` `qa_viewport` (the `lc_qa_viewport` control command, window `set_size` and `outer_position`, `qa-native` feature only) had no caller. The native journeys set the viewport with `rightkit_qa::control::Control::set_viewport` (rightkit-qa 0.9.0, `embedded` `set_viewport`) and read geometry back through the shell's `windows::readback` (`lc_qa_window_state`).

## 1. Close guard for the main window

**RightKit issue:** [bogusyogi/rightkit#1150](https://github.com/bogusyogi/rightkit/issues/1150). Ledger expiry 2026-11-30 (legacy sunset).

- **Code:** `native.rs` `.on_window_event` `CloseRequested` for `main`, plus the `closing` / `shutdown_complete` state.
- **What the user loses:** closing the main window while an import, export or preview build is running, or while the catalog has unsaved changes, would quit without the guard:
  - running work would be lost;
  - the "save before closing?" prompt (`lc://close-requested`) would never appear;
  - the session owner would not be shut down in order (`host.shutdown_process`), so the catalog journal would not be flushed.
- **Why the published API can't do it:** the shell's `CloseRequested` handler only saves window state and implements close-to-tray (rightkit-tauri-shell 0.6.0 `src/lifecycle.rs:551-566`). There is no hook through which the app can veto or defer a close. The quit drain in `quit.rs` covers `ExitRequested`, not a window close.
- **Other apps:**
  - pulse destroys the window on close (`lib.rs:660-669`);
  - heardright runs a close animation (`app_run.rs:546-574`).

  Neither has to protect unsaved document state.
- **Proof:** `active_close_reason` (`native.rs`), the unsaved-close path that emits `lc://close-requested`, the handler at `desktop.tsx:698`, and the forced close from `DialogHost.tsx:219` after the user confirms.
